## 0. 一句话目标

**让一个人用多条本地 CLI agent 并行推进一个真实项目：每一步都能验证、能回退、能接手。**

拆成三个关键词：

- **并行**：多条线同时干活，而不是排队等一个人做完
- **可验证**：产物能定位到文件与字节数，结论能逐字回查
- **可接手**：换 Agent、隔几天、出故障，都能从现场继续

**不是**什么（同样重要）：不是"全自动做游戏"，不是多人协作平台，不是云端 SaaS。

## 2. 目标用户与使用场景

**主用户**：单人开发者（一人工作室式），同时推进游戏、自媒体、外包多条线。
特征：懂技术但不希望盯每一步；要的是"能验证的结果"，不是"看起来很忙的 Agent"。

**次要用户**：外部审计者——只读代码与文档，不进界面。

| 场景 | 触发 | 期望结果 | 现状 |
|---|---|---|---|
| S1 派大活 | 有一件需要多线协作的事 | 主控拆段、派线、收口，产物落盘 | ✅ |
| S2 问状况 | 想知道"现在卡在哪" | 秒回真实任务状态，不编 | ✅ 对话注入任务快照 |
| S3 叫停转向 | 方向错了 | 停止 → 一句话改方向 | ✅ 停止 + 续跑；对话不能打断进行中的轮次 |
| S4 开新线 | 活没有归属线（跨线合成、独立审计） | 主控申请 → 人审批（可改参数）→ 落盘 | ✅ |
| S5 复盘 | 想知道"这活到底干没干成" | 看轮次、产物、证据、耗时、token | ✅ 任务详情 + SSE |
| S6 换项目 | 接到新项目 | 改配置即可跑 | 🟡 有文档，未实战 |
| S7 外部审计 | 交给别人评审 | 有可独立阅读的文档与可复现命令 | ✅ 三份文档 + 本地可跑 |

## 5. 关键约束

1. **一实例一项目**：一份 `agents.toml` + 一份 `.data`。多项目要起多实例（不同 `MA_PORT` / `MA_HOME`）。
2. **Windows 为主**：开发和实测都在 Windows；核心是 Node，其他平台未验证。
3. **Node >= 22.6**：直接跑 `.ts`（类型剥离），因此**没有构建步骤，也没有类型检查**。
4. **CLI 是一次性调用**：`codebuddy -p` 跑起来不收新输入，所以"叫停"只能杀进程。
5. **无用户体系**：一把访问令牌，没有账号与权限分级。
6. **SQLite 单写者**：`hub.db` 靠单例锁保证只有一个进程写。

## 7. 验收标准

### A. 任务级（一次真实任务跑完）

- [ ] 主控给出 `plan` 时，**全部段落跑完**任务才 `done`；中途不因收口上限阻塞
- [ ] 每轮有回执；`pass` 至少 2 条证据，能在产物里**逐字**搜到
- [ ] 产物路径在工作区内（或 `extra_dirs` 白名单），越界判 `rework` 而非放行
- [ ] 失败轮次留下"写了但没通过"的清单，不静默丢弃
- [ ] 任务详情能看到：轮次、耗时、token、产物、失败原因

### B. 系统级（门禁）

- [ ] `npm test` 全绿（当前 191 项 / 190 过 / 1 跳过）
- [ ] `npm run verify` 全绿（**待建**：`typecheck && test`）
- [ ] 并发写配置不丢节点（20 并发用例）

### C. 安全级

- [ ] LAN 无令牌 → 401；带令牌 → 200；错误令牌 → 401
- [ ] 产物 HTML 默认 `CSP: sandbox`，无 `allow-same-origin`
- [ ] `access="read"` 在 codebuddy 上被拒（400 / SKIPPED），不静默降级
- [ ] `nodeId="../x"` 三处接口均 400

### D. 运维级

- [ ] 从其他目录启动，`/api/tasks` 能读到全部历史任务
- [ ] 崩溃后重启，进行中的任务标 `interrupted`，可续跑
- [ ] `npm run doctor` 无 fail 项

## 8. 不明确或缺失的需求

> **2026-11-21 已全部拍板，决策见第 10 节。** 本节保留为当时的提问清单存档，不要再按这里的"建议默认"实现。

| # | 问题 | 为什么重要 | 建议默认 |
|---|---|---|---|
| 1 | **成功指标未定义**：什么算"这个项目成了"？ | 没有指标就无法判断该继续加功能还是收尾 | 连续 5 个真实任务无需人工干预即可收口，且产物全部可验证 |
| 2 | **用户范围**：只自己用，还是要给别人用？ | 决定要不要做账号、多租户、审计日志 | 只自己 + 可信协作者；不做账号 |
| 3 | **多项目并行**：现在一实例一项目，够不够？ | 决定要不要引入 project 维度 | 先一实例一项目；需要时起第二实例 |
| 4 | **验收终审权**：全自动通过，还是必须人签？ | 全自动快但风险高；人签慢 | 高风险动作（删/移/改协议）人签，其余自动 |
| 5 | **成本上限**：单任务允许花多少 token / 多少钱？ | 现在只有轮次预算，没有金额熔断 | 单任务 5M token 或 30 分钟，超了停下问人 |
| 6 | **数据保留**：`.sandbox`、日志、历史任务留多久？ | 不清理会无限涨；清理又可能删掉证据 | 任务结束后 30 天归档；证据类不删 |
| 7 | **失败自动恢复**：`interrupted` 要不要自动续跑？ | 现在必须手动点 | 自动续跑一次，仍失败则停 |
| 8 | **对话写权限**：只出方案，还是允许改小文件？ | 影响安全边界与便利性 | 保持只读；要改就派任务 |
| 9 | **provider 范围**：codex / codebuddy 之外必须支持谁？ | 决定适配层与只读能力的实现 | 先保 codebuddy（主力）+ codex（唯一可只读） |
| 10 | **通知渠道**：任务结束要不要发邮件/IM？ | 长任务不想一直盯屏幕 | 只做站内提示；需要再加 |
| 11 | **远程访问**：LAN 明文 HTTP 是否可接受？ | 令牌会明文过网 | 只在内网；敏感场景走 SSH 隧道 |
| 12 | **多语言**：界面与文档是否要英文？ | 影响是否对外开源 | 先中文；开源前再评估 |
