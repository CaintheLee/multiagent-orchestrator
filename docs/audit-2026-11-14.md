## 一、已修（3 处）

### 1. `process.exit()` 截断输出

**位置**：`cli.ts` 四处退出点

**问题**：Node 的 stdout 写管道是异步的，`process.exit()` 会立即终止进程，缓冲区里没 flush 的内容直接丢失。

**证据**：今晚后台跑 `#9~#11` 时，`tail -20` 拿到空输出，但 `runs.json` 里明明有记录。排查时误以为进程没启动。

**修法**：改成 `process.exitCode = N` + `return`，让 Node 自然退出。

### 2. `runs.json` 非原子写

**位置**：`store.ts` `saveRun`

**问题**：`writeFileSync(FILE, ...)` 直接覆盖。如果写到一半崩溃（或磁盘满），文件变成半截 JSON，下次 `loadRuns` 解析失败**静默返回 `[]`**——所有历史记录一次性消失，且没有任何报错。

**修法**：写 `.tmp` 再 `renameSync`。rename 在同一分区是原子操作。

### 3. stdout 无上限

**位置**：`adapters.ts`

**问题**：模型有时会把整个文件内容打回 stdout。一次 10MB 输出会全量堆在字符串里，`parseReceipt` 还要对它跑正则。

**修法**：stdout 累积上限 4MB，stderr 上限 64KB，超出直接丢弃后续。

## 二、未修，但要知道（按严重度）

### 高｜并发写会丢记录

`saveRun` 是 read-modify-write，没有锁。两个 CLI 同时跑会互相覆盖。

**当前影响**：单进程串行跑，碰不到。
**什么时候会出问题**：做界面之后，多个请求同时触发保存，或者手动开两个终端跑。
**修法方向**：SQLite（`node:sqlite` 自带）或文件锁（`fs.open` 的 `wx` 标志）。

### 中｜超时只杀父进程

`child.kill('SIGKILL')` 在 Windows 上只杀直接子进程。codex 自己会起 node 子进程，父进程被杀后它们可能变孤儿，继续占 CPU。

**证据**：今晚多次超时后，`codex` 相关进程是否残留没有验证。
**修法方向**：Windows 上用 `taskkill /T /F /PID`，或用 Job Object。

### 中｜配置不检测环

`loadConfig` 检查 `parent` 指向的节点存在，但不检查成环（a→b→a）。

**当前影响**：`runTree` 靠轮次预算 6 兜住，不会无限递归，但会白跑 6 轮才停。
**修法方向**：加载时用 visited 集合走一遍。

### 低｜回执取「最后一个代码块」

`parseReceipt` 用 `matchAll` 取最后一个 `agent-autoloop` 块。如果模型在正文里又写了一个示例块（放在最后），会取错。

**当前影响**：给模型的示例是写在提示词里的，正文复述的概率不高。
**缓解**：`summary` 长度、字段白名单这些校验会把明显不对的挡掉。

### 低｜记录无限增长

`runs.json` 只追加不轮转。跑几千轮后文件会很大，每次 `loadRuns` 全量解析。

**修法方向**：按月分文件，或直接换 SQLite。

## 四、整体判断

**结构是干净的**：配置、协议、适配器、存储、命令行五个文件，依赖单向，没有一个文件超过 200 行。

**真正的风险不在代码，在运行时**：
- codex 约四分之一概率静默卡住（已加重试，但重试本身也可能撞上）
- 执行者耗时从 20 秒到 424 秒不等，跟任务复杂度不线性相关
- codebuddy 在当前环境下拿不到登录态（`cbc -p` 直接返回 Authentication required）

这三条都不是代码能解决的，需要在界面层让人看见「这一轮卡了多久、在干什么」。

## 五、审计方式说明

这次审计不是静态读代码，而是**先看今天 22 轮的真实记录，再去代码里找对因**：

```
#1  FAILED  300.0s  没有找到回执块      → 定位到 prompt 走参数会卡死
#4  DONE    266.2s  未能创建文件        → 定位到 a 不知道 b 的工作区
#8  FAILED  300.0s  没有找到回执块      → 定位到 codex 偶发卡住
#17 FAILED  120.0s  没有找到回执块      → 定位到收口轮需要更长时间
```

每条失败都能追到一个具体的设计缺陷或外部约束，没有一条是「不明原因」。
