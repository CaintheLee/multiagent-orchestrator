# 贵模型指点，便宜模型干活

> 这个项目的核心命题：不是"让 AI 多干活"，是"**让贵的 token 花在刀刃上**"。
> 本文回答三件事：钱花在哪、怎么分、怎么防止白烧。

---

## 一、钱到底花在哪

跑一轮派活，token 消耗是极不均匀的：

| 角色 | 一轮输出 | 折算 token | 占比 |
|---|---|---|---|
| 主控派活 | 一句话 + 一份任务说明 | ~1500 | 8% |
| 执行者写代码 | 三千字 HTML + 回执 | ~6000 | 32% |
| 主控收口 | 一句话判断 or 三段式打回 | ~2000 | 11% |
| **执行者重做** | 又是三千字 | ~6000 | 32% |
| 主控再收口 | 一句话 | ~800 | 4% |
| 提示词（每轮必发） | 1.5–2KB | ~2000×5 | 13% |

**结论：执行者占六成以上，主控占两成，提示词占一成。**

而且**打回一次，执行者的六成就再花一遍**。

### 于是就有三条铁律

1. **贵模型只做短输出的活**——判断、拆解、写反馈，不写代码
2. **便宜模型干长输出的活**——写文件、改文件
3. **打回要贵**——每打回一次，等于把最贵的那部分重付一次

---

## 二、怎么分模型

```toml
[root]
id = "a"
name = "主控"
model = "deepseek-v4-pro"      # 贵，但只输出判断
timeout_min = 6

[agent.b]
parent = "a"
name = "执行者"
model = "hy4free"              # 免费，干全部体力活
timeout_min = 10
```

**为什么这么配**：

- 主控每轮输出 500–2000 字，贵模型跑得起
- 执行者每轮 3000–8000 字，用贵模型会贵十倍
- 主控的判断质量决定执行者干得对不对，**这是杠杆点**

**一句话**：贵的 8% 决定便宜的那 60% 值不值。

### 什么时候该反过来

如果任务本身是"**一次性的、不需要验收的**"（比如"把这段文字翻译成英文"），那执行者用强模型、不需要主控。

**只有需要"拆解 + 反复改"的活，分层才划算。**

## 三、审计这件事，有个悖论

用户提的「audit agent 截断无意义循环」——**方向对，但用 agent 实现是错的**。

**理由**：让一个模型去审"有没有浪费 token"，本身就是一次 token 消耗。而且：

- 它每审一次都要读上下文（几千 token）
- 它可能审错（把正常的重试判成空转）
- 它自己也可能陷入"我再看看"的循环

**正确的做法**：**用规则审，零 token。**

审计要回答的问题只有三个，都能用算术答：

| 问题 | 怎么判 | 成本 |
|---|---|---|
| 轮次超预算了吗 | 计数 | 0 |
| 同一件事打回太多次了吗 | 数 verdict=rework 的条数 | 0 |
| 两次打回说的是同一段话吗 | 比较字符串 | 0 |

**所以才叫「守门员」（guard），不叫 audit agent。**

## 四、空转的三种样子

### 形态 1 · 反复打回同一件事

```
a 打回 b：缺「早起的鸟儿有虫吃」
b 改：加了，但写成「早起鸟儿有虫吃」（少一个「的」）
a 打回 b：还是缺
b 改：又写成「早起的鸟儿有虫吃」✅
a 收口：通过
```

三轮打回，执行者白跑两遍。**这是最贵的空转**。

**对策**：同一件事打回满 2 次就停，交给人。

### 形态 2 · 打回意见重复

```
第一次打回：不合格，缺少 X，请补上 X
第二次打回：不合格，缺少 X，请补上 X     ← 一模一样
```

说明**执行者没理解，或者主控没看执行者的新输出**。再打回第三次也一样。

**对策**：比较两次打回的指令，前 80 字完全相同 → 判定卡死，停。

### 形态 3 · 执行者原地打转

执行者的输出里反复出现"让我再试一次"、"还是不行"、"换一种方法"。

一轮跑满 10 分钟，产出一个错误的文件。

**对策**：跑完后检查输出里这些词的密度，超过阈值就标记"这轮是空转"。

## 五、守门员怎么判

```ts
// kernel/guard.ts —— 纯函数，不调模型，不读文件
type Verdict = { stop: false } | { stop: true; why: string };

function guard(runs: RunRecord[], budget: number): Verdict {
  if (budget <= 0) return { stop: true, why: '轮次预算用完' };

  const reworks = runs.filter((r) => r.verdict === 'rework');

  // 形态 1：同一件事打回两次，第三次不该再试
  if (reworks.length >= 2) {
    return { stop: true, why: `同一件事已打回 ${reworks.length} 次，需要人看一眼` };
  }

  // 形态 2：两次打回给的是同一段话
  if (reworks.length === 2) {
    const [first, second] = reworks;
    const a = (first.dispatch[0]?.task ?? '').slice(0, 80);
    const b = (second.dispatch[0]?.task ?? '').slice(0, 80);
    if (a && a === b) return { stop: true, why: '两次打回给的是同一段指令，在空转' };
  }

  return { stop: false };
}
```

**调用点**：`runTree` 每次要派下一轮之前调一次。

```ts
const g = guard(loadRuns(), budget);
if (g.stop) {
  log(`守门员叫停：${g.why}`);
  return rec;                    // 停下来，把现有结果交出去
}
```

**关键设计**：停下来不是"失败"，是"交回现状 + 说明为什么停"。人来看一眼，决定继续还是换思路。

## 六、还要防一件事：提示词税

每轮都要发 1.5–2KB 的提示词，五轮下来就是一成 token。

**砍的办法**：

1. 角色提示词（`prompts/*.md`）**只留判断标准**，不要写背景故事
2. 收口轮的 brief 只带**产物原文前 1200 字**，不带整份文件
3. 打回指令**不要复述原始任务**（执行者上轮已经有）

**现在的问题**：`prompts/executor.md` 里有一半是"你要交什么"的重复说明。可以砍到 8 行。

## 七、一句话总结

```
贵模型：拆、判、骂（短输出，占 8% token，决定成败）
便宜模型：写、改、重写（长输出，占 60% token，执行到位就行）
守门员：算术题（0 token，防止前两者空转）
```

**打回是这个系统最贵的动作**——它让最贵的那部分重付一次。所以打回必须带具体改法，而不是"不行，重做"。

## 五、后来补的：证据（evidence）

守门员能数次数，数不出「一次就放水」：主控没打开文件，凭下级一句「做完了」直接判 pass，guard 看不出来。

补的办法还是零 token：

- 回执多一个 `evidence` 字段，要求判通过时给 2 条以上**从产物里原样复制**的片段
- 程序拿这些片段去产物文件里逐字搜索（`kernel/settle.ts` 的 `verifyEvidence`），一条搜不到就不给 pass
- 有产物却一条证据都不给，同样不算通过
- 判了 pass 但证据核不上时，把「你的结论被驳回 + 哪几条搜不到」拍回给主控，让它重读一次产物再判；只补一次，第二次还核不上就以 `rework` 结束

为什么这招有效：小于 6000 字节的文本产物，内容会被塞进收口简报，抄一段很容易；但大文件（比如 10KB 的 HTML）不进简报，主控想给证据就必须真的打开它。编造的、概括的、改过标点的片段都搜不到。

边界：evidence 只能证明「它引用了文件里的原话」，证明不了「它逐条对了验收标准」。要后者，只能上真正的 auditor agent（见第三节的取舍）。
