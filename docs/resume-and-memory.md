# 断点续跑、成本可见、任务流水、provider 表

> 2026-11-16，四项一起做。前一项解决「重启即报废」，后三项让成本和质量变得可看可查。

---

## 一、断点续跑

### 先说清它不是什么

**不是恢复会话。** codebuddy 走的是 `-p` 一次性调用，没有可 resume 的 native session id（那是 Codex 和 AutoSwarm 的做法）。所以「接着上次那句话往下说」在这里做不到。

### 它实际是什么

**把「已经交付了什么」写进新任务的正文，让主控只补缺的部分。**

`POST /api/tasks/:id/resume`：

1. 取原任务的正文
2. 查 `runs` 表里该任务所有 `state='done'` 的轮次，每个节点只取最后一次
3. 读每轮的 json，拿到 summary 和产物文件名+字节数
4. 拼成新任务：

```
<原任务全文>

## 这是任务 #19 的续跑（它当时没跑完：interrupted）
下面这些已经交付，**不要重做，也不要覆盖已有文件**：
- a：完成《示例项目》献祭写实统一执行标准… · 产物：SACRIFICIAL_REALISM_MASTER_STANDARD.md（12610 字节）
- b：已写出 character_art_standard.md… · 产物：character_art_standard.md（7344 字节）
- c：已交付 item_art_standard.md… · 产物：item_art_standard.md（5580 字节）

只补还没完成的部分。派活时说清哪些跳过，收口时只验收这次新交付的。
```

5. 新任务入队，照常跑

界面上：任务处于 `interrupted / failed / canceled / blocked` 时，页头出现「续跑 #19」，点了就建新任务并跳过去。

### 为什么不自动续跑

自动续跑等于替用户决定「再花一次钱」。**默认不花**，由人点。重启后任务仍标 `interrupted`，只是按钮变成可点。

### 验证

任务 #19（五条线只完成两条）点续跑 → 生成 #28：

```
#125 主控 102s  派出: d,e,f        ← 只派缺的三条，b/c 和总纲跳过
#126 d / #127 e / #128 f 同时跑    ← 车位 3/3
```

## 二、成本可见

真 token 数拿不到——codebuddy 的文本输出里没有 usage，改成 `--output-format json` 会打乱回执解析。所以先记**代理指标**：

- `RunRecord.model`：这一轮用的哪个模型
- `RunRecord.promptBytes`：提示词字节数

界面的轮次列表里显示成 `#126 d DONE kimi-k3.1-pro 8KB↑ 102.0s`。至少能看出「哪条线用贵模型、输入多大」。

真 token 要等验证 codebuddy 的 json 模式，那是另一件事。

## 三、任务流水（跨任务记忆）

新增 `.data/memory/journal.md`：

```
- 2026-11-16 12:47 · #28 未完成 · 阅读"D:/YourProject\docs\ART_DIRECTION_…
- 2026-11-16 12:20 · #27 完成 · 【派生审批验证】这一单必须走 spawn…
```

- 任务进终态时由 scheduler 追加一行，**纯拼接，不调模型**
- 只留最近 40 条
- 派活时给「有下级的节点」注入最近 15 条，标题是「## 这个项目最近做过的任务（先看这里，别重复劳动）」

它和另外两份记忆的分工：

| 文件 | 内容 | 谁写 |
|---|---|---|
| `context.md` | 项目是什么、该读哪几份权威文档 | 人写 |
| `lessons.md` | 上次是怎么被骗的、验收该防什么 | `learn` 从打回里提炼 |
| `journal.md` | 最近做过哪些任务、成没成 | 系统自动追加 |

## 四、provider 表

`adapters/table.ts` 从 2 个扩到 4 个：`codex`、`codebuddy`、`claude`、`gemini`。后两个是「装了就能用」——找不到可执行文件时会被 `runOnce` 的 catch 接住，记一轮 failed 并说明缺什么，不影响别的 provider。

`/api/agents` 现在下发 `plugins: [{id, label}]`，界面的两处 provider 下拉都改成由它填充，不再写死。新增一个 CLI 只需改 `table.ts` 一处。

## 五、两项没做

### 消息总线（agent 之间点对点通信）

AutoSwarm 有 `peers`，但那是为「长期协作会话」设计的。我们的任务是跑完即结束的一次性链路，子 agent 之间直接对话会带来三个问题：谁授权、谁负责死锁、产物归属怎么算。现在由主控转述已经够用，加这层只会让收口语义变模糊。

### DAG 拓扑

树已经覆盖绝大多数场景，派生补上了动态性。换成图要重写 dispatch 语义、收口逻辑、UI 布局，风险远大于收益。当前没有「一个产物同时喂给两条线」的真实需求——真有的话，主控把路径写进两条 dispatch 的 task 里就行。

## 测试

89 项（88 过 + 1 skip）。新增的续跑与流水逻辑靠手工验证（`#19 → #28` 只派 d/e/f），没有写自动化用例——它依赖真实任务历史，构造成本比收益高。
